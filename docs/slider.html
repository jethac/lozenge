Slider

Styled native <input type="range"> (Material's Slider, Lozenge-flavoured): 4px rounded track, 16px accent thumb, hover halo, focus ring. Behavior is 100% the platform's. HONEST LIMITATION: the filled portion of the track is painted from a --value custom property (0..1) that the APP must set on the input — inline style="--value: 0.6" for static values, or one line of app JS on input: el.style.setProperty('--value', el.value / (el.max || 100)). Without --value the track degrades gracefully to unfilled; the control still works.

Root: .slider on <input>

Examples

Example 1
<input type="range" class="slider" min="0" max="100" value="60" style="--value: 0.6" aria-label="Estimate">
Example 2
<input type="range" class="slider slider-compact" min="0" max="10" value="3" style="--value: 0.3" aria-label="Story points">

Accessibility

OnAttributeLevelWhen
.slideraria-labelrequiredno visible <label for> or aria-labelledby references the input

All interaction is the native range input: arrow keys step, Home/End jump, drag works, form participation is standard. Name the control with a visible <label for> or aria-label. If min/max aren't self-evident, add aria-valuetext via your app. Remember --value only paints the fill — keyboard/pointer changes move the native value regardless, so keep the two in sync with the one-liner above (or accept an unfilled track).
